# Pi configuration import

The coding resource transaction merges the shared Pi defaults, seven `subagents.agentOverrides` role model/thinking pairs, exact-version package declarations, and the `reui` MCP entry into the native agent configuration. It preserves unknown settings, other roles and servers, credentials and sessions; locally changed managed entries block rather than being overwritten. Previous receipts and checkouts whose Pi settings contain only `skills: []` remain supported. If a checkout has no `stack/configs/pi/mcp.json`, it does not manage the user's MCP file.

Each package entry has an exact npm version and `skills: []`. Pi 1.5.2's native package filters exclude the package-provided skills, including those from `pi-subagents`; the existing checkout `shape`, `implement`, and `verify` skills remain. The package's other resources, including its prompts, are not disabled by that filter. Package versions are independent of the CLI's npm dependencies; the backup's npm installation tree and lock are not imported.

Normal Pi startup can use its native package manager to resolve or install a missing configured package and may run package installation scripts. Normal startup can also connect to the configured remote MCP server. This is separate from Agent Stack's core setup proof: its isolated Pi TUI uses a temporary agent directory and does not load these optional package declarations or the reui configuration. `validate`, `doctor`, and setup planning do not install or execute the seven packages. Offline or `--no-mcp` can be used in a dedicated validation environment when testing the core TUI without optional network access. The native `mcp.json` is consumed by Pi's built-in MCP support; disabling or replacing that extension can change whether it is used.

Verification of Pi's native settings, package-resource filtering, and MCP parser with offline local stubs does not prove real third-party extension behavior, remote service availability, credentials, or model calls. Do not commit tokens, sessions, package caches, bookkeeping fields such as `lastChangelogVersion` and `extensionChangelogVersions`, or backup skills. Pi's verified bookkeeping fields are ignored in the readiness signature; other settings remain checked.
